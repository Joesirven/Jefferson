Summary

Build and run Jefferson's first validation experiment: a static backtest of Wake County NC precinct 01-07 against its certified Nov-2020 result, executed as an iterate-until-pass loop governed by success determinants D1–D5, with an experiment tracker and monitoring dashboard built before any LLM spend. The pipeline runs on the ba-sing-se VPS with DuckDB as the warehouse. This revision is hardened: six assumptions were tested live (one failed — no inference API key exists; one changed the design — the certified precinct file is election-day-only, so ground truth moves to the precinct-sorted file), and every fallback in this document is grounded in an observed result, not a guess. The plan is written for handoff: a cheaper executor agent implements, tests, and loops; all judgment calls are pre-made here or routed to escalation.

Problem Frame

The architecture rethink (T9) ruled that the cheapest decisive experiment — can prompted off-the-shelf AI voters reproduce one known election result? — runs before any training, replay, or planner work. Competitor research showed the loop form needs hard stop conditions and an anti-overfitting holdout rule; a five-persona document review then found the protocol holes (memorization leakage, holdout retakes, luck-passes) that this revision closes. The backend code is broken (malformed packaging, mangled LLM client), the VPS has no toolchain, and the prior handoff agent advanced only website/taste work — so this plan assumes a cold start by its executor.

High-Level Technical Design

The pipeline is a gated, linear flow with one tuning loop and one terminal exam. Every poll→score cycle writes a tracker record. The loop's only exits: all determinants pass (and replicate, and survive the holdout exam), the budget ceiling is hit, or a human stops it.

Key Technical Decisions

KTD-1 · Ground truth = the precinct-sorted results file, with a declared noise band. E3 proved the certified results_pct precinct rows are election-day-only (~9% of votes, Republican-skewed). Primary truth is results_precinct_sort/WAKE_PRECINCT_SORT.txt, where all voting methods are re-sorted to home precincts (verified 01-07: Biden 2,022 / Trump 527). Its own header declares deliberate statistical noise (NC GS §163-132.5G); at ~2,600 votes the noise is small relative to the 4-pt threshold, but scoring records it as a ground-truth uncertainty band and cross-checks county totals against results_pct and MEDSL.
KTD-2 · Inference fallback chain (E1 failed — no key exists). In order: (1) Jose creates a DeepInfra key (ADR-003 standing choice; Qwen/Qwen3-14B, $0.12/M in, $0.24/M out — Qwen3-8B is no longer served, hence the ADR-003 amendment); (2) fal.ai with the existing FAL_KEY if it serves a Qwen3-class open-weight instruct model with JSON output (executor verifies via fal's model search before use; if used, the ADR-003 amendment names it); (3) any OpenAI-compatible serverless host serving Qwen3-14B. Whatever resolves must pass G3's smoke test. Self-hosting on the VPS is not an option (no GPU), and switching providers does not change what the model memorized — see the leakage risk.
KTD-3 · Fresh async OpenAI-compatible client; quarantine the legacy code. src/tasks/llm.py is unrepairable (missing class statement, absent imports, sync-in-async). The LLMClient ABC + provider-factory pattern survives in a new module. Prefect-era modules and stale tests move to backend/legacy/ so uv run pytest can pass clean.
KTD-4 · Streaming UTF-16 conversion, Wake-only parquet, delete raw. unzip -p | iconv -f UTF-16LE -t UTF-8 so the UTF-16 intermediate never hits disk (the unpacked file is likely 10–15 GB, not the 3–5 first estimated); explicit kept-column list (no name/address/phone); deletion is a logged step asserted in G1. DuckDB memory_limit ≈ 1 GB and temp_directory in a jose-owned path (E5: ~2.4 GB available RAM, swap exhausted). The precinct-sort file additionally needs tr -d '\000' and trailing-space field trims (E4).
KTD-5 · Collapsed subgroup reporting. One-way margins (party, race, age, sex) plus a party×race two-way; the spec's four-way grid is statistically empty at n=300. The cell list is locked at G4's cell audit before scoring. NCSBE race_code (incl. ~10–15% Undesignated) + ethnic_code and party UNA get first-class buckets.
KTD-6 · Turnout oracle with attrition gate. Individual voter history (ncvhis92) is the oracle only if its 2020 ballot count for the precinct is within 5% of certified ballots cast; otherwise auto-downgrade to precinct-aggregate turnout. The current-roll file silently loses voters who moved or died since 2020.
KTD-7 · Resume-safe polling. Personas persisted to parquet pre-polling with stable persona_idx; every response keyed (persona, sample, question) and appended to JSONL; resume replays missing tuples; per-persona sample counts must be equal or the run is flagged. Structured output: thinking mode disabled, JSON response format, enum-constrained choices including "don't know", ≤2 retries, hard call ceiling.
KTD-8 · Analytics foundation = skills-over-semantic-layer, minimal v1 tonight. Scoring metrics are defined as named DuckDB views with co-located markdown doc files — the Anthropic internal pattern adapted to vault + Meadow + Claude Code (ruled by Jose; OpenAI's standalone-agent/embedding-index pattern rejected for a solo operator). The scorer consumes these views, so the foundation serves the pipeline from day one. Recorded as proposed ADR-006.
KTD-9 · Holdouts sealed early, in a committed config. Two Wake precincts chosen during U3 — one suburban/rural per ADR-001, one competitive (presidential margin < 15 pts, per E6) — written to backend/data/config/holdouts.json, ingested by the tracker, excluded from every loop query until FREEZE.

Success determinants (the loop's stop condition)

D1Headline accuracyTwo-party vote-share error ≤ 4 pts on practice precinct (≤ 6 on holdouts) AND beats both baselines (uniform swing from 2016; demographics-only logit on CES NC). D2Subgroup honestyWeighted-mean subgroup error ≤ 8 pts; no single group worse than 12 (collapsed cells per KTD-5)Verasight's published subgroup bar: 8 pts

Standards the executor holds to

  • Evidence standard: no claim without a tracker run record; every number in the results doc links to the run that produced it.
  • Code standard: plain asyncio (no Prefect), src.-rooted imports, pytest green before any VPS deploy, type-validated structured outputs.
  • Privacy standard: R4 absolute; parquet extracts carry an NCSBE-restriction notice; prompts contain zero voter-identifying data.
  • Loop standard: R11/R17/R19/R20 are mechanical rules, not judgment calls; prompt diffs recorded every iteration; gates never softened under time pressure — a gate judgment made under pressure is itself a tracked record.
  • Claim standard: nothing is called "validated" except a D5 pass, and only with the within-county, within-cycle scope attached.

Executor Contract

This plan is executed by a cheaper-model agent. The division of authority is fixed:

Executor MAY decideMechanical implementation choices inside a unit's spec: function decomposition, variable naming, test fixture shapes, retry timings, SQL phrasing, dashboard layout details (within the Mobbin-referenced direction). Anything where two reasonable choices both satisfy the unit's test scenarios.
Executor MAY NOT decideDeterminant thresholds and gates (R13); prompt geography (R17); holdout identities or any holdout read before FREEZE (R11); scope changes (adding/removing units or requirements); standing-decision changes (those are ADRs, signed by Jose only); skipping a failed gate; any external communication; any spend beyond the env-configured ceiling; calling anything "validated" (claim standard).
Escalation protocolOn any blocked state (gate failure with no named fallback, provider chain exhausted, vault hook conflicts, data surprises not covered by E1–E6): write a blocker record to the tracker (what was attempted, exact error, which fallback was tried), commit work-in-progress to the worktree branch, and stop. Do not improvise around a block. Jose-owed items at handoff: DeepInfra key (KTD-2 step 1) and the CES Dataverse download (U3).
Definition of doneAll nine units verified per their Verification fields; D1–D5 evaluated with the loop run under protocol (whatever the outcome — a well-documented fail is a valid result); results doc written with gap interpretation; vault artifacts committed through the frontmatter hook; session closed per vault rules (AGENTS-LOG row, agents.json flip, eval run, git ledger commit).

Execution order: U1 ∥ U2 → U3 ∥ U4 → U5 → U6 → U7 → U9 loop; U8 parallel throughout. The tracker (U4) must be live before the first paid call (R8).
